# Wave 3 preparation: frozen doc encoder × causal query attention (2026-10-09)

Code changes (branch `wave3-prep`, commits on top of `ec469c0`) that make the wave-3 cells of `reports/ablation_clean_v3_2026-10-07.md` runnable on the clean v3 recipe, and comparable with round 1's `single` / `multi` (cell D: joint doc encoder, bidirectional).

| cell | doc encoder | query attention | flags |
| --- | --- | --- | --- |
| C | frozen (base weights) | bidirectional | `--freeze_doc_encoder` |
| A | frozen | causal | `--freeze_doc_encoder --force_causal` |
| B | joint | causal | `--force_causal` |
| D (round 1) | joint | bidirectional | – |

## 1. Frozen classes against the current joint classes

`EmbeddingModelFrozenDocEnc` carried copies of the joint class's `forward()` and `generate()`. Compared line by line with `EmbeddingModelDocEncNoProj` at `ec469c0`, the copies were current: same generation loop, scheduled sampling (`sampling_rate` from `finetuning_multi.py`, including `--sampling_saturate_frac`), teacher feeding with shuffled golds, per-step teacher cosine, pairwise cosine, `add_geometry_stats`, and the loss from `build_loss` (the base constructor). The only differences were the doc encoder and `is_causal=self.force_causal` on the query-encoder calls. `EmbeddingModelFrozenDocEncSingleQuery` already inherited the joint single-query `forward()`. Hard negatives are a data-loader matter and identical.

Change: the copies are removed. The frozen classes override only `__init__` and `encode_documents`, and inherit `forward()` / `generate()`, so they cannot drift from the joint classes again. The causal option moved into the joint classes (section 3).

Remaining differences other than the frozen weights: documents are encoded under `no_grad` (intended), in bf16 weights (the joint run computes them in bf16 under autocast/FSDP mixed precision; same arithmetic), and the copy is in `eval()` mode before `model.train()` (Qwen2 has no dropout layers, so no effect).

## 2. FSDP

Root cause of "rank 1 receives no gradients" (2026-09-25): the accelerate config wraps the whole model as **one** FSDP unit (needed for multi-query, see the config comment). The frozen copy was flattened into the same flat parameter as the trainable encoder; FSDP splits the flat parameter evenly across the 2 ranks, and the copy, equal in size and registered second, filled nearly all of rank 1's shard. Rank 1 therefore owned (almost) no trainable weights.

Fix (`finetuning_multi.py`, `utils.set_optim`): the copy is passed to FSDP as an **ignored module** (`FullyShardedDataParallelPlugin(ignored_modules=[doc_encoder])`, accelerate 1.9.0): it is replicated on each rank in bf16 and never sharded, and FSDP shards only the trainable encoder, as in the joint runs. The copy is left out of the optimizer (it was in it before, without gradients).

**Verification** (`GRAD_DIAG_STEPS=10`, per-rank `[graddiag]` lines; jobs `19510168`, `19510171`; 10 steps, clean v3 + hard negatives, same seed):

| --- | --- | --- | --- |
| D (joint) | 2-GPU FSDP | 771.6M / 771.6M | all (142 / 197) |
| C (frozen) | 2-GPU FSDP | 771.6M / 771.6M | all (142 / 197) |
| C (frozen) | 2-GPU DDP | 1,543.3M each (replicated) | all (338) |

## 3. Causal query attention (cell B, and A)

infly's `Qwen2Model.forward` defaults `is_causal=False` and builds a causal 4-D mask (SDPA and eager paths) only when the caller passes `is_causal=True`; `config.is_causal` is not read. New helper `inbatch.query_attention_kwargs(model)` returns `{"is_causal": True}` under `--force_causal`, else `{}`, and is spread into every **query**-encoder call: the multi-query training loop and `generate()`, and the single-query forward. Document encoding never gets it. Without the flag the calls are unchanged (no kwarg), so D and waves 1–2 are unaffected.

Inference: multi-query retrieval calls `model.generate()`, which applies it. Single-query retrieval calls the bare encoder, so `load_retriever` sets `retriever._force_causal` from the checkpoint's options and `retrieval_inf.embed_queries_single` passes `is_causal=True` when it is set.

The single-query partner of A and B is also causal (`--force_causal` applies to its one query pass), so each cell compares single and multi under the same attention.

## 4. Checkpoints and evaluation

- `utils.save_state_dict` drops `doc_encoder.*` keys, so frozen checkpoints hold only the query encoder (same size as D's, ~7.1 GB) instead of ~13 GB. No effect on joint models (no such keys).
- `inbatch.load_model_state` (used by the in-training `evaluate()` and by `load_retriever`) is strict except that `doc_encoder.*` may be missing; the class constructor loads the copy from the base model, i.e. exactly the weights it had in training.
- Corpus embedding: `gen_embed_new.py` already embeds with `retriever.doc_encoder` when present (frozen copy = base weights); queries use the trained query encoder.
- **Shared corpus embedding** (`full_eval_queue.sh SHARED_EMB=<dir>`): every frozen checkpoint embeds the corpus with the same base weights, so one embedding serves all of their full evals: no per-checkpoint embedding job, retrieval is submitted at once, and the shared embedding is never deleted. Build it once with `gen_embed_ckpt.sbatch` using **a frozen checkpoint** as `CKPT` (any step of a C/A run, e.g. its first saved one), so it goes through the same `doc_encoder` path at 512 tokens; not from the bare HF model id, which `gen_embed_new.py` would load as a SentenceTransformer. Frozen runs use their own queue file (`full_queue_qampari_clean_v3_abl2_frozen.txt`) served by workers with `SHARED_EMB`; B uses the regular queue.
- Cheap evals are unchanged (each checkpoint embeds the reduced corpus itself, ~3 GB, through the same `doc_encoder` path).
- `tools/param_drift.py` compares the checkpoint's keys against step 0's, both without the copy: unaffected.

- Save/load round trip (C multi, step-20 checkpoint, in-training evals at steps 10 and 20 loaded it fine: MRR 0.941, 0.948): checkpoint 7.10 GB with 0 `doc_encoder.*` keys; `load_retriever` rebuilds the copy bit-identical to the base retriever (max |diff| 0.0); the query encoder equals the checkpoint in all 338 tensors (323 differ from the base); `gen_embed_new.py`'s rule picks the frozen copy for the corpus.

Diagnostics: `GRAD_DIAG_STEPS=N` (environment, off by default) makes every rank log, for the first N steps, its trainable tensors, how many have gradients and optimizer state, the local and global gradient norms and the loss (`finetuning_multi._grad_diag`). Useful as a first-steps check of any new backend or model class.

## 6. Launch spec

`abl2_launch.sh wave3 [C|A|B]` (default: all three cells), each run through `phaseC_run.sh` with `DENSE=1 KEEP_TOP=3 KEEP_FINAL=1`, LR 1e-5, `--train_data clean_v3_hn --negative_hard_ratio 0.5`:

| run | mode | extra flags |
| --- | --- | --- |
| `clean_v3_abl2_qampari_C_single` | single | `--freeze_doc_encoder` |
| `clean_v3_abl2_qampari_C_multi` | multi | `--freeze_doc_encoder` |
| `clean_v3_abl2_qampari_A_single` | single | `--freeze_doc_encoder --force_causal` |
| `clean_v3_abl2_qampari_A_multi` | multi | `--freeze_doc_encoder --force_causal` |
| `clean_v3_abl2_qampari_B_single` | single | `--force_causal` |
| `clean_v3_abl2_qampari_B_multi` | multi | `--force_causal` |

Order C → A → B. Before the first frozen full eval: build the shared corpus embedding once (~77 GB, kept until all frozen evals are done) and start the frozen-queue workers with `SHARED_EMB`.

**Disk per run:** checkpoints ~7.1 GB each (frozen copy not saved), up to 10 before pruning (~71 GB), 4 after (top 3 + final, ~28 GB). Full evals: B ~77 GB of corpus embedding per in-flight eval (as D); A/C none per eval, one shared ~77 GB. **GPUs:** 2 per training run; with the 16-GPU per-user cap, at most ~6 concurrent trainings leave room for cheap evals.
